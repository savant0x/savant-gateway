# FID: CI typecheck generates Next types first

**Filename:** `FID-2026-1103-142-ci-typecheck-typegen.md`
**ID:** FID-2026-1103-142
**Severity:** high
**Status:** closed
**Created:** 2026-11-03
**Automation level:** 3
**YAGNI-Compliance:** Verified — one command in the existing gate, no new dependency.

## Summary

GitHub Actions failed at `npm run typecheck` on the pushed commit `c889d83`:

```text
components/content/content-media.tsx(7,27): error TS2307:
Cannot find module '@/assets/thumb.jpg' or its corresponding type declarations.
```

The asset is tracked. The missing declaration is `next-env.d.ts`, which is
gitignored and generated by `next dev` or `next build`. CI runs typecheck before
build, so a clean checkout has no image-module declarations even though the
asset exists. Local typecheck passed only because a development server had
already generated the file.

## Impact Assessment

- **Affected components:** `package.json` typecheck script, CI workflow, pre-push
  hook, contributor setup.
- **Risk:** high — every clean checkout fails the mandatory typecheck gate before
  the first build, and CI cannot go green on a correct tree.

## Proposed Solution

1. **implemented:** run `next typegen` before `tsc --noEmit` in the existing
   `typecheck` script, matching the Next 16 CLI documentation.
2. **implemented:** keep `next-env.d.ts` and `.next/` generated and ignored; do
   not commit generated files or duplicate Next's image declarations.
3. **implemented:** verify from a state with no `next-env.d.ts` that typegen
   recreates it and typecheck passes.

## Verification Gates

- `npm run check`
- `npm test`
- `npm run quality`
- `npm run build`
- GitHub Actions `ci` workflow on the pushed commit

## Perfection Loop

### Loop 1 — RED/GREEN/AUDIT/ADVERSARIAL

- **RED:** CI typecheck failed on a tracked JPEG import because `next-env.d.ts`
  did not exist in the clean checkout.
- **GREEN:** typecheck now generates route and image types before invoking tsc.
- **AUDIT:** confirmed `assets/thumb.jpg` is tracked at `origin/main`, and that
  `next-env.d.ts` is gitignored and contains the `next/image-types/global`
  reference the import needs.
- **ADVERSARIAL:** a missing `.next` directory, a running dev server, a clean CI
  checkout and a contributor without a prior build must all behave the same.
  Typegen writes only ignored files and adds no runtime dependency.
- **CHANGE DELTA:** 3%; converged.

### Missed Questions

1. **Should `next-env.d.ts` be committed?** No; Next regenerates it and the
   repository already ignores it. The gate should create its own prerequisites.
2. **Should CI run build before typecheck?** No; that would hide the same defect
   behind a slower gate and couple typecheck to a successful build.

## Implementation Evidence

- **Commit SHA:** `b6604af` (the first commit after `c889d83`).
- **Implementation:** `package.json` → `"typecheck": "next typegen && tsc --noEmit"`.
- **Local receipt:** removed `next-env.d.ts`, ran `npm run typecheck`; output
  `Generating route types... ✓ Types generated successfully` and exit 0.
- **CI receipt:** GitHub Actions run `41706820863` (`ci`) passed every gate on
  `b5afbe5`, which contains this fix. The prior run `41696668303` failed at the
  typecheck step as quoted above.
- **Archived:** yes — moved to `dev/fids/archive/` after the green workflow.
